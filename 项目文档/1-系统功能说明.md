## 1. 系统是做什么的

本项目是 **肝癌基线数据 → 死亡风险二分类** 的数据工厂，主要产出两类东西：

1. **LLM 微调语料**（主路径）：病历原文 → 死亡风险 `0/1` 的 JSONL（Alpaca / Messages）
2. **表格特征集 + 基线模型**（对照路径）：结构化特征 CSV + Logistic / HGB 指标

另外提供：

- **可视化看板**（`web/`）：看清洗 QC、队列、LLM 语料与表格基线摘要
- **DuckDB 仓库**（`warehouse/`）：给大模型 Text2SQL / 工具调用查数

当前 **没有独立 HTTP API 后端**；`server/` 是可重复执行的 Python 脚本流水线。

## 2. 功能一览

| 功能 | 入口 | 说明 |
|---|---|---|
| 原始数据清洗去重 | `server/build_training_dataset.py` | 合并 `原始数据/` 多分片 → `output/` |
| 文本规则特征 | `server/extract_text_features_a.py` | 从旁路文本抽癌栓/腹水等开关特征 |
| Task A 表格集 | `server/build_task_a.py` | 划分 train/val/test、打 `label_death` → `dataset/task_a/` |
| LLM 微调数据 | `server/build_llm_dataset_a.py` | 拼病历原文 → `dataset/task_a_llm/*.jsonl` |
| 表格基线训练 | `server/train_baseline_a.py` | 写 `dataset/task_a/baseline_metrics.json` |
| DuckDB 建仓 | `server/build_duckdb_warehouse.py` | → `warehouse/hcc_llm.duckdb` |
| 只读试查 | `server/query_duckdb_demo.py` | 模拟工具层 SELECT |
| 可视化看板 | `web/`（Vite + React） | 日常验收与汇报 |

## 3. 数据流（开发时务必对齐）

```text
原始数据/*.csv|xlsx
        │
        ▼
server/build_training_dataset.py
        │
        ├─► output/dedup_raw.csv
        ├─► output/text_fields_sidecar.csv   （病历旁路）
        └─► output/train|val|test.csv 等
        │
        ├──────────────────────┐
        ▼                      ▼
extract_text_features_a   build_task_a.py
        │                      │
        ▼                      ▼
dataset/task_a/          dataset/task_a/
  text_features.csv        features_*.csv / patients.csv
                               │
                ┌──────────────┼──────────────┐
                ▼              ▼              ▼
        build_llm_dataset_a  train_baseline  build_duckdb_warehouse
                │              │              │
                ▼              ▼              ▼
        dataset/task_a_llm/  baseline_*.json  warehouse/hcc_llm.duckdb
```

**看板数字不会自动跟磁盘同步。**  
`web/src/lib/qc-data.ts`、`task-a-data.ts`、`task-a-llm-data.ts` 是汇总快照；流水线重跑后若指标变了，需手动改这些文件再刷新/重建前端。

## 4. GitHub 有什么 / 本地还要什么

| 内容 | 是否在 GitHub | 说明 |
|---|---|---|
| `web/`、`server/`、`项目文档/`、`docs/` | 是 | clone 即可开发看板与脚本 |
| 看板汇总数字（`web/src/lib/*-data.ts`） | 是 | **只看页面**不需要另拷数据 |
| `原始数据/`、`output/`、`dataset/`、`*.duckdb` | 否 | 含患者级数据；重跑流水线或本地联调需另拷 |

**仅查看看板：** clone → `cd web && npm install && npm run dev`  

**需重跑流水线：** 另备 `原始数据/`（必要时连同已生成的 `output/`、`dataset/`、`warehouse/`），放到仓库根后再按 `0-启动说明.md` 执行。

## 5. 继续开发怎么下手

### 改看板 UI / 图表

- 主文件：`web/src/App.tsx`
- 样式与组件：`web/src/components/`、`web/src/index.css`
- 改端口：`web/vite.config.ts` 的 `server.port`，或  
  `npm run dev -- --host 0.0.0.0 --port <端口>`

### 改清洗 / 标签 / 特征

1. 先读 `3-死亡风险分类-特征构建规则.md` 与 `docs/label_spec_a.md`
2. 改配置优先动 `server/config/task_a.py`（泄漏列、关键词、路径）
3. 再改对应 `build_*.py` / `extract_*.py`
4. 在**项目根**用 `.venv` 重跑脚本，检查 `output/`、`dataset/`
5. 如需看板同步，更新 `web/src/lib/*-data.ts`

### 改 LLM 语料格式

- 配置：`server/config/task_a_llm.py`
- 逻辑：`server/build_llm_dataset_a.py`
- 验收：`dataset/task_a_llm/summary.json`、样例 JSONL；看板侧栏 **LLM Dataset**

### 改 DuckDB / Text2SQL

- 配置与表白名单：`server/config/duckdb_warehouse.py`
- 建仓：`server/build_duckdb_warehouse.py`
- 说明：`5-DuckDB数据仓库说明.md`

### 约定

- Python 命令在**仓库根**执行，例如：  
  `python server\build_task_a.py`
- 建议：`set PYTHONNOUSERSITE=1`（Windows）避免用户目录包污染
- 不要把 `原始数据/`、大体量 CSV/JSONL、`.duckdb` 推到 Git
