# 死亡风险分类 · 大语言模型（LLM）数据集构建规则

> **任务定位**：微调 / 训练大语言模型，根据**基线时点**的病历文本，判断死亡风险（`label_death` 0/1）。  
> **不是**表格特征工程任务；`X_train.csv` 那套树模型数据仅作可选对照，不作为本规则主路径。

---

## 1. 任务定义

| 项 | 约定 |
|---|---|
| 任务 | 死亡风险二分类（可表述为生成式判断） |
| 时点 | 基线就诊 / 入院时已有信息 |
| 输入 | 病历文本包（+ 可选基线表型摘要） |
| 输出 | 模型生成的标签（及可选简短结论，**不得**抄死因） |
| 标签来源 | `death` → `label_death`（0/1） |
| 样本粒度 | 一行 / 一条 = 一名患者（`patient_sn`） |

---

## 2. 一条样本长什么样

推荐同时导出两种常见微调格式（内容等价）：

### 2.1 Alpaca 风格（`*.alpaca.jsonl`）

```json
{
  "patient_sn": "...",
  "split": "train",
  "label_death": 0,
  "instruction": "根据以下肝癌相关患者的基线病历，判断死亡风险。只回答 0 或 1：0=低风险/随访未死亡，1=高风险/发生死亡。不要编造病历中未出现的检查。",
  "input": "【基线摘要】...\n【主诉】...\n【现病史】...\n【诊断】...",
  "output": "0"
}
```

### 2.2 Chat / ShareGPT 风格（`*.messages.jsonl`）

```json
{
  "patient_sn": "...",
  "split": "train",
  "label_death": 0,
  "messages": [
    {"role": "system", "content": "你是肝癌临床风险助手。根据基线病历判断死亡风险，只输出 0 或 1。"},
    {"role": "user", "content": "【基线摘要】...\n【主诉】..."},
    {"role": "assistant", "content": "0"}
  ]
}
```

## 3. 输入文本：要哪些 / 不要哪些

### 3.1 要进「病历文本包」的字段（按优先级拼接）

| 优先级 | 字段 | 段落标题 |
|---|---|---|
| 高 | `chief_complain` | 【主诉】 |
| 高 | `last_visit_history_of_present_illness` / `present_illness_history` | 【现病史】 |
| 高 | `last_diagnosis` / `main_diagnosis` / `disease_name` / ICD 名称 | 【诊断】 |
| 中 | `positive_symptom` | 【阳性症状】 |
| 中 | `past_history` / `personal_history` / `family_history` | 【既往史】等 |
| 中 | `pre_disease_name` / `infectious_disease_name` | 【基础病/传染病】 |
| 中 | `exam_conclusion` / `auxiliary_exam` | 【检查结论】 |
| 中 | `surgical_name` / `description`（基线前治疗相关） | 【手术/操作】 |
| 低 | `physical_exam` / `specialist_exam` | 【查体】（易很长，截断） |
| 低 | `imaging_conclusion` / `immunohistochemistry_result` | 【影像/病理】 |

可选一行 **【基线摘要】**（非原文，由表型拼）：性别、年龄、肝炎/肝硬化相关开关等——只作提示，不能替代病历。

### 3.2 禁止进入输入（泄漏 / 无效）

| 类型 | 字段 |
|---|---|
| 结局泄漏 | `death`、`death_reason`、`death_time`、`death_or_last_visit_date`、`follow_up_days` |
| PII | `name`、住院号、`patient_id`、病理号等 |
| 伪文本 | `diagnosis_date`、`diagnosis_sequence`、检验裸数值未对齐列 |
| 空/噪声 | `gross_finding`、`comments`（医嘱模板）等 |

**硬规则**：死因叙述、死亡时间、随访天数 **永远不能** 出现在 `input` / `user` 里。

### 3.3 长度控制

- 整段 `input` 建议上限：**6000 汉字**（可按模型上下文改）
- 截断顺序：先压【查体】【影像】，再压过长现病史尾部；**保留主诉与诊断**
- 某段为空则整段省略，不写「无」占位（避免假阴性暗示），除非原始记录明确书写

---

## 4. 输出标签怎么写

| 模式 | `output` / `assistant` | 适用 |
|---|---|---|
| **A. 纯标签（默认）** | `0` 或 `1` | 分类微调、评测 AUROC/准确率最干净 |
| B. 短句 | `死亡风险：低` / `死亡风险：高` | 更自然语言 |
| C. 结构化 JSON | `{"label_death":0}` | 便于解析 |

默认采用 **模式 A**。  
禁止用 `death_reason` 生成「解释」当监督信号（严重泄漏）。

---

## 5. 样本纳入 / 排除

| 规则 | 说明 |
|---|---|
| 必须有标签 | `label_death ∈ {0,1}` |
| 必须有可用文本 | 文本包去空白后长度 ≥ `MIN_CHARS`（默认 40） |
| 可选亚组 | `cohort_hcc_strong=1` 可另存 HCC 子集 |
| 不确定标签 | `label_uncertain=1`（如死亡无随访）默认仍保留，但可打标供过滤 |

划分：与患者级 `train/val/test` 一致（复用已有划分，避免泄漏到测试患者）。

---

## 6. 与旧「表格 Task A」的关系

| | 表格 Task A（旧） | LLM Task A（本规则） |
|---|---|---|
| 主文件 | `X_*.csv` / `y_*.csv` | `dataset/task_a_llm/*.jsonl` |
| 模型 | Logistic / HGB | Qwen / 其他 LLM 的 SFT/LoRA |
| 病历 | 抽成 0/1 特征 | **原文进入 input** |
| 地位 | 可选基线对照 | **当前主路径** |

规则抽取的开关特征（癌栓、腹水等）**可以**写成【结构化提示】附在病历后，但不是必须；首版以原文为主。

---

## 7. 评测怎么做（LLM）

1. 在 `test` 的 JSONL 上生成，解析出 0/1  
2. 相对 `label_death` 算 Accuracy / F1 / AUROC（若有概率）  
3. 抽查：input 中不得出现死因、死亡日期  
4. 报告按 split 的样本量、正例率、平均 input 长度
